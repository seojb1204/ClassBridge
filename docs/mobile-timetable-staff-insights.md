# 모바일 일간 시간표 + 교수자 상담 정보 페이지

## 확정 UX 동작
- 화면 너비 720px 이하에서는 **목록 보기(기본)** / **일간 시간표 보기** 버튼을 노출한다.
- 학생 상담 예약, 교수자 상담 시간 관리, 교수자 예약 관리에서 공통 시간표 컴포넌트를 사용한다.
- 모바일 시간표는 한 날짜에 한정한 시간 축을 사용한다. 30분과 60분은 같은 비율(30분 48px, 60분 96px)로 표시한다.
- 목록/시간표 전환은 현재 선택한 날짜, 예약 상태, 기존 예약/취소 권한을 변경하지 않는다. 이 기능은 새로운 DB 데이터나 별도 API가 필요 없다.
- 모바일 터치가 어려운 좁은 7열 PC 시간표를 그대로 축소하지 않고 일간 축만 렌더링한다.

## 새 교수자·관리자 상담 정보 페이지
- 경로: `#/staff/insights`.
- 노출 대상: **교수자·관리자**. 학생은 메뉴에서 숨겨지고 API에서도 403 응답이다.
- 통계 API: `GET /api/staff/overview?days=90` (1~365일).
- 상담 기록 API: `GET /api/staff/notes?q=검색어&offset=0&limit=20` (최대 50건).
- 통계 항목: 기간 내 예약 건수, 상태별(예약 중/완료/미참석/취소), 기록 작성 건수, 열린 상담 슬롯 수, 향후 14일 예약 수, 완료·미참석으로 **판정된** 상담의 완료율, 상담 유형·진행 방식 분포.
- 기간 기준: **상담 시작일**이 해당 기간에 속하는 예약. 단순히 오늘 이전에 등록한 신규 예약 수가 아니다.
- 기록 목록: 작성된 `bookings.professor_note`만 전 기간에 걸쳐 조회. 학생 이름·학번·상담기록을 검색하고 페이지 단위로 조회. 개인정보가 있는 전체 학생명부를 새 화면에 다운로드하는 기능은 추가하지 않았다.
- 기록 수정: 기존 `PUT /api/bookings/{id}/note`를 호출. DB 스키마 변경 없음. 기록은 기존 예약과 연결된 상태로 보존.
- 사용자 기입 학번은 학교 검증값이 아니다.
- 개인정보: 학생에게 비공개 기록을 노출하지 않고, 통계는 익명 설문·건의함의 참여자/작성자 정보를 조회하지 않는다. 결과를 브라우저 localStorage에 저장하지 않는다.

## 개발·운영 경계
- 신규 DB 마이그레이션 없음.
- 무료 Render/Neon 요금제 유지.
- Render의 현재 실배포 브랜치와 커밋은 별도로 확인한다. 개발 브랜치를 승인 전에 배포하거나 병합하지 않는다.
- 실제 학생 데이터 수집·보유·삭제 정책은 별도의 공개 전 정책 검증 항목이다.

## 검증 기대 결과
1. 모바일 학생 화면에서 목록 → 일간 시간표 → 목록 전환해도 같은 날짜/상담이 선택된다.
2. 일간 시간표에서 예약 가능·내 예약·마감 상태를 구분하고 상담을 터치하면 기존 동작이 실행된다.
3. 교수자/관리자 화면에서 상담 기록과 통계를 볼 수 있고 기존 비공개 기록을 검색·수정할 수 있다.
4. 학생/미인증 사용자에게 두 통계·기록 API는 각각 403/401을 반환한다.
5. 완료율은 분모가 (완료+미참석)이고, 예약 중/취소 상태는 분모에 포함하지 않는다.
6. 설문 응답·익명 건의 작성자는 새 화면/API에서 노출되지 않는다.
7. 기존 예약·상담 기록·Neon production/staging 데이터에 대한 삭제/초기화가 없다.

## 후속 확장 (이번 변경 범위 아님)
- 학기별 상담 통계/수업별 분석은 교수자 여러 명·학기 데이터 정책을 정한 이후 설계.
- 익명 설문/건의의 집계 지표는 익명성 검토 및 운영 활성화 결정 전에는 통계에 섞지 않는다.
- CSV 내보내기/외부 분석은 상담기록 개인정보 보관·접근 정책 승인 후 검토.
