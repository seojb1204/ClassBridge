# 예약 알림·설문 삭제·학생 계정 정리

이번 범위는 구현과 로컬 검증이다. 운영 DB 적용, 병합·배포, 실제 메일·휴대폰 알림 발송은 하지 않았다.
기준 배포 커밋: c7a0a9067ffd633f442a24d6aad25b89448340c8 (staging).

## 사용자 동작

- 게시 중인 설문도 편집창의 삭제 버튼 또는 목록의 휴지통 버튼으로 바로 숨긴다. 같은 트랜잭션에서 종료 상태로 바꾸므로 복원해도 다시 공개되지 않는다. 기존 답변은 보존하며 영구 삭제는 기존 확인 절차를 유지한다.
- 관리자 계정·권한 화면에서 학생 계정의 연결 기록을 먼저 확인한다. 예약·취소 이력·설문 참여·개발자 메시지·작업 이력 등 사용자 외래키 참조가 하나라도 있으면 삭제를 거부한다. 로그인 세션만 있으면 삭제할 수 있다. 학생·교수자에게 계정 삭제 권한을 주지 않는다. 관리자·교수자·본인 삭제는 거부한다.
- 실제 삭제 순간에 다시 잠금과 연결 기록 검사를 한다. DB 외래키도 동시에 추가되는 기록을 보호한다. 삭제는 가입 차단이 아니며 Google 재로그인이 가능하다. 익명 답변·건의는 사용자와 연결되어 있지 않으므로 찾아 삭제하지 않는다.
- 예약 마지막 자리는 DB 조건부 갱신으로 선착순 처리한다. 실패한 학생에게 다른 학생이 먼저 예약했다는 안내와 새 가용 시간을 제공한다. 전체 상담 취소와 개인 변경이 겹쳐 DB 교착이 발생하면 전부 롤백하고 재시도를 안내한다.

## 알림 설계

마이그레이션 0008은 notification_outbox와 push_subscriptions 두 테이블만 추가한다. 기존 기록을 수정·삭제하거나 과거 예약에 알림을 소급 생성하지 않는다. 새로운 외부 서버·유료 서비스는 만들지 않는다.

예약 신청·취소·변경 및 교수자 대리 처리, 전체 상담 시간 취소, 예약이 있는 상담 장소 등의 변경은 예약과 같은 트랜잭션에 알림을 저장한다. 별도 프로세스 없이 기존 웹서버의 작업 스레드가 처리하며 최대 유휴 대기는 60초이다. 네트워크 전송 동안 DB 잠금을 잡지 않는다.

- Gmail: 학생 이름, 사건 종류, 예약번호, 상담 시각(변경 전·후), 로그인 필요한 사이트 링크만 포함한다. 발신자 seojb1204@gmail.com, 수신자 icekorean@gmail.com을 설정할 예정이며 학생에게 보내지 않는다. 이름은 신청서 기재값이다.
- 푸시: 지정된 교수자의 등록 기기별로 별도 대기 기록을 만든다. 이름·학번·연락처·상담 내용은 저장하거나 전송하지 않고 상담 시각과 변경 안내만 표시한다. Android Chrome의 FCM 주소만 허용하며 다른 임의 URL과 리디렉션은 차단한다.
- 예약 실패·롤백 시 알림도 저장되지 않는다. Gmail 장애는 이미 저장된 예약을 되돌리지 않는다.
- 명확한 일시 실패는 지수 간격으로 최대 8번 시도한다. 전송 후 응답 유실·서버 재시작 등 발송 여부가 불명확하면 uncertain으로 남기고 자동 재전송하지 않는다. 정확히 한 번 전달을 보장하지 않는다.
- 같은 예약 흐름·채널·기기의 순서를 보존한다. 앞선 알림의 미확인 오류가 있으면 뒤의 알림도 대기한다. Gmail 재인증 문제는 푸시를 막지 않는다.
- 운영 설정의 예약 알림 상태에서 실패·인증 오류·불확실한 발송을 확인하고, 실제 발신함·기기를 확인한 뒤 재시도/수신 확인/발송 제외를 선택한다. 이것은 외부 자동 장애 통지 기능은 아니다. `sent`는 제공자의 요청 접수이지 실제 수신 증명이 아니다.

## 휴대폰 수신 조건과 한계

교수자가 Android Chrome에서 로그인 후 메뉴의 휴대폰 알림 → 이 기기에서 알림 받기를 선택하고 기기 권한을 허용한다. 앱 설치와 알림 허용은 별개다. 앱을 닫아도 유효한 로그인·기기 권한·통신 상태에서는 수신할 수 있다.

구독은 로그인 세션에 연결된다. 로그아웃·역할 변경·비활성화로 세션이 삭제되면 구독도 삭제되고, 만료된 세션에는 발송하지 않는다. 현재 설정의 로그인 유효기간을 바꾸지 않았다(코드 기본값 12시간). 만료 후 재로그인하고 알림 받기를 다시 눌러야 한다. 보안상 장기 로그인으로 임의 변경하지 않았다. 기기 한도는 10개이다.

서비스 워커도 표시 직전 같은 사이트의 현재 로그인·지정 교수자 여부를 다시 확인한다. 오프라인에서 이 확인을 할 수 없으면 표시하지 않는다. 제공자 대기 유효시간은 5분이며 통신·절전·OS 설정으로 전달이 늦거나 누락될 수 있다. 중요 일정 확인의 유일한 수단으로 취급하지 않는다.

## 운영 설정 절차 — 아직 실행하지 않음

먼저 현재 서비스(staging 브랜치)와 DB 대상을 다시 확인하고 0008 적용·배포 승인을 받는다. 예시 환경 파일은 변수 이름과 빈 값만 포함한다. 실제 비밀값은 사용자가 Render 비밀 설정에 직접 입력하며 채팅·Git·로그에 넣지 않는다.

GMAIL_NOTIFICATIONS_ENABLED, GMAIL_CLIENT_ID, GMAIL_CLIENT_SECRET, GMAIL_REFRESH_TOKEN,
GMAIL_SENDER_EMAIL, GMAIL_PROFESSOR_EMAIL을 로그인용 GOOGLE_CLIENT_ID/SECRET과 별도로 설정한다.
사용할 Gmail 클라이언트는 classbridge-notification 프로젝트의 발송용 클라이언트이며, 기존 토큰과 같은 클라이언트인지 확인해야 한다.

PUSH_ENABLED, PUSH_PUBLIC_KEY, PUSH_PRIVATE_KEY, PUSH_PROFESSOR_EMAIL, PUSH_CONTACT_EMAIL을 설정한다.
수신 교수자는 icekorean@gmail.com, 운영 연락처는 seojb1204@gmail.com이다. 키는 P-256 공개키(65바이트)와 비밀 스칼라(32바이트)를 각각 URL-safe base64(패딩 제외)로 보관한다. 운영 키는 이번 검증에서 생성·등록하지 않았다. 시작 시 키 쌍 일치를 검사한다.

두 기능은 기본 비활성화다. 환경값을 등록한 후 채널별로 true를 설정해야 새 예약부터 기록한다. 기능이 꺼져 있던 기간의 알림을 자동 복구하지 않는다.

Google 공식 문서에 따르면 Gmail send는 민감 권한이며 Testing 상태의 갱신 토큰은 일반적으로 7일 제한이 있다. Playground 기본 클라이언트는 24시간 후 토큰을 철회하므로 자체 클라이언트를 사용해야 한다. In production 전환과 앱 심사 여부는 별도 문제이며, 현재 콘솔의 게시·브랜딩 상태는 이번 작업에서 확인하지 않았다. 토큰은 철회·만료될 수 있고 코드의 인증 오류는 운영 설정에서 표시된다.

- https://developers.google.com/identity/protocols/oauth2/production-readiness/overview
- https://developers.google.com/workspace/gmail/api/auth/scopes
- https://developers.google.com/oauthplayground/
- https://developers.google.com/identity/protocols/oauth2/resources/best-practices
- https://github.com/web-push-libs/pywebpush

실제 발송 시험은 승인된 가상 예약 내용과 수신 주소를 먼저 확정한다. 운영 학생 데이터로 임의 시험하지 않는다. 교수자 휴대폰의 실제 수신·권한 허용은 교수자 본인이 확인해야 한다.

## 복구

발송 문제는 먼저 해당 ENABLED 설정을 false로 바꾸어 신규 기록·발송을 중단한다. 대기 기록은 보존된다. 다시 켜면 기존 대기 기록도 처리할 수 있으므로 먼저 상태를 검토한다.
코드 복구 시 0008 마이그레이션 파일과 새 DB 테이블은 유지한다. 0008을 모르는 옛 커밋을 그대로 배포하면 시작 명령의 alembic upgrade가 실패할 수 있으므로, 0008을 보존하는 복구 브랜치에서 기능 코드를 되돌린다. 운영 DB downgrade나 테이블 삭제는 하지 않는다.
휴지통 설문은 복원 가능하다. 연결 기록 없는 학생 계정의 실제 삭제는 코드 복구로 되돌아오지 않으며 재로그인으로 새 계정이 만들어진다.

## 범위 밖

네이버 예약을 참고한 학생 모바일 예약 화면 전체 개편은 앞서 제시한 개선안 단계로 유지했다. 이번 승인 답변은 알림의 구현·로컬 검증과 연결 기록 없는 학생 계정 삭제 정책을 확정한 것이다. 실제 계정·설문 삭제, 운영 변경, 메일 발송, 모바일 실제 수신 시험은 실행하지 않았다.
