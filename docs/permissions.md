## 추가 규칙 (서비스 계층)

- 자기 자신의 역할 변경과 비활성화는 불가하다. 셀프 승격도 막힌다.
- 마지막 활성 관리자는 강등하거나 비활성화할 수 없다.
- 역할 변경·비활성화 시 대상자의 모든 세션을 즉시 삭제한다.
- 역할 변경, 계정 상태 변경, 설정 변경, 교수자의 예약 대리 생성·취소·변경, 상담 시간 취소는 감사 로그에 남긴다.
- 학생의 예약 API 응답에는 상담 기록(`professor_note`)이 포함되지 않는다.
- 초기 역할: `ADMIN_EMAILS`, `PROFESSOR_EMAILS`는 **계정을 처음 만들 때만** 적용된다. 예외적으로 활성 관리자가 0명이면 `ADMIN_EMAILS`에 있는 기존 계정을 관리자로 복구한다(감사 로그 기록).
- 사용자는 이메일이 아니라 Google `sub`로 식별한다. 같은 이메일이 다른 `sub`로 들어오면 자동 병합하지 않고 거부한다.

## 개발자 문의

- 모든 로그인 역할은 문의를 작성하고 본인 문의만 조회·추가 답변할 수 있다 (`slot:view` + 소유자 검사).
- 다른 이용자의 문의는 관리자만 개발자 문의함에서 확인한다. 교수자에게 별도 열람 권한을 주지 않는다.
- 개발자 문의는 계정에 연결된 비공개 대화이며 기존 익명 건의와 테이블·API를 분리한다.
- 관리자의 답변·처리 상태 변경은 문의 내용 없이 작업 이력에 남긴다.
- 미확인 건수는 관리자들이 공유하며, 새 답변·상태 변경은 작성자에게 표시한다. 완료 후 작성자가 추가 내용을 보내면 재접수한다.
- 화면 주소는 서비스 내부 경로만 받으며 URL 쿼리·쿠키·비밀번호·자동 진단 자료는 수집하지 않는다.
- 외부 이메일 알림·첨부파일·자동 삭제는 제공하지 않는다. 마지막 처리일로부터 최대 365일의 보관 상한을 운영자가 관리한다.
