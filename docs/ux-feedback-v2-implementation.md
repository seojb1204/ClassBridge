# ClassBridge UX 피드백 v2 — 구현·검증 추적

## 기준과 제약
- 기획상 교수자 1명 + 관리자 1명. 다중 교수자 지원은 별도 기획으로 보류.
- 학생 개인 Gmail 허용 정책 유지. 현재 스테이징은 별도의 테스트 계정 허용 목록으로 제한.
- 익명 설문/건의함은 개인정보·익명성 승인 전 비활성화 유지.
- 기존 DB 마이그레이션 0004, 기존 학생 예약·상담 기록 삭제/초기화 없음.
- 본 브랜치에서 수정한 코드는 Render에서 자동 배포되지 않음. 운영 DB 변경·배포는 승인 후 별도 진행.

## M0 — 로그인·권한 보안
- 현장 보고의 `dev_login=true`는 **현 배포된 Python production 코드와 모순**된다.
- 생산 환경용 API 응답이 `dev_login=false`이고 개발 로그인이 404인지 회귀 테스트 추가.
- 유지보수 브랜치의 기존 개발용 관리자→검증된 Google ID 연결 패치 포함. 다른 실제 Google 계정은 이메일만으로 병합하지 않음.
- 실제 HTTPS 환경에서의 로그인/권한 및 외부 Google 인증 실험은 배포 후 검증 필요.

## M1 — 모바일·달력·상태 표현
- 상담 15분 눈금의 **고정 픽셀 크기**: 30분/60분 길이 비교 시 같은 배율.
- 교수자는 전체 상담 슬롯 수, 학생은 선택 가능한 슬롯 수가 날짜 칩에 표시됨.
- 모바일 상담카드는 청록색 예약 가능, 파란색 예약됨, 회색 마감 등 **문구+색상**으로 구분.
- 모바일 상단 계정 정보는 메뉴 펼침 상태에서만 표시하고, 자주 쓰는 3개 메뉴와 더보기를 하단에 배치.
- 교수자 모바일에서 시간표를 먼저 보여주고 등록 폼을 접음.
- 모바일 상담 불가일 날짜 입력칸의 잘못된 170px 높이 수정.
- 가능한 상담이 있는 가장 가까운 날짜로 처음 이동하도록 개선.
- 예약 정책은 서버 DB의 실제 설정을 읽어 학생에게 안내.

## M2 — 예약 관리 통합
- 학생: 시간표에서 본인 예약 선택→상세·취소. 다른 가능 시간 선택→일정 변경.
- 교수자: 예약 관리의 달력 보기(기본) / 목록 보기 전환.
- 예약된 시간 선택→상담 대상·기록 작성/저장·취소·완료 처리.
- 목록은 학번·이메일 등 검색/이력 관리용으로 유지하고, 보조 작업은 더보기 메뉴로 정리.
- 기존 `bookings.professor_note` 사용. 데이터 이관 및 별도 기록 테이블 추가 없음.

## M3 — 상담 시간 계획·교체
- 반복·대량 등록 전 생성 수, 겹침 수, 예약된 슬롯 수 **미리보기**.
- 새 `POST /api/slots/preview`: 확인용이며 DB를 바꾸지 않음.
- 새 `POST /api/slots/replace`: 미리보기에서 확인한 기존 슬롯 ID만 대상으로 미예약 슬롯을 취소 상태로 보존하고 교체.
- 예약자가 있는 시간은 자동 교체 금지, 예상과 달라진 미리보기는 재확인 요청.
- 교체는 단일 DB 트랜잭션, PostgreSQL GiST 겹침 제약 유지, 실패 시 롤백.
- 미예약 슬롯에 한하여 시작·종료 시간을 화면에서 변경. 예약 중인 시간은 수정 차단.
- 상담 불가일 해제 전 확인 대화상자 추가.
- **정책:** 기존 예약을 자동으로 다른 시간에 이전하거나 삭제하지 않음.

## M4 — 접근성·캐시·편의
- 모달에서 중복 전송 차단, Escape 닫기, 탭 이동 제한, 종료 후 원래 버튼 포커스 복귀.
- .js/.css/.html 정적 자원은 배포 후 재검증하도록 `Cache-Control: no-cache, must-revalidate`.
- 학생 상담 예약을 외부 전송 없이 `.ics` 파일로 다운로드해 기기 캘린더에 추가 가능.
- 학생 이름은 기존 로그인 기본 프로필에서 한 번 채움. **학번 저장·자동 재사용 기능은 보유기간 정책 미정이므로 구현하지 않음.**
- 이메일 알림/자동 노쇼 리마인더는 발송 제공사·비용·개인정보 정책 승인 후 추후 진행.

## M5 — 검사와 배포 경계
- 관련 서비스·API 단위/통합, PostgreSQL 정원/겹침, 브라우저 E2E를 GitHub CI로 검증.
- 모바일 375/390px 화면에서 시간표 우선 배치, 날짜 입력 높이, 메뉴 노출과 화면 너비 검사.
- 자동 테스트의 통과는 실제 학생·교수자의 **실기기 사용성 검증**과 다름.
- Playwright 다운로드 테스트는 개인정보가 없는 ICS 파일 생성만 확인.
- 스테이징 업데이트는 CI 성공·변경 영향 검토 후 사용자 승인 시 수동 배포.
- 기존 계정 3개와 예약 데이터는 초기화하지 않음.
- Neon/Render 실제 백업 복구 실험과 개인정보 정책은 이 UX 작업과 별도의 운영 마일스톤으로 유지.

## 완료 확인 시나리오
1. 학생이 로그인→가능한 상담 날짜·시간 인식→예약→자신의 슬롯에서 취소/다른 시간 선택 변경.
2. 30/60분 상담 혼합 주간 시간표 배율 일치.
3. 교수자가 모바일 첫 화면에서 시간표 확인, '+상담 시간 등록'을 열어 미리보기 후 등록.
4. 미예약 상담만 안전 교체. 예약 중이면 기존 예약·기록 보존 및 변경 거절.
5. 교수자가 시간표에서 학생 상세/상담 기록 작성/예약 취소 및 상태 변경.
6. 키보드 Escape·Tab, 375px 화면, 중복 제출 시 단일 서버 처리.
7. 최소 하나의 실제 Google 관리자·교수자·학생 테스트 계정으로 스테이징 검증.
